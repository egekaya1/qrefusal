# Is 4-bit quantization more than noise to a chat model's safety behaviour?

*Attributing behavioural shifts with matched perturbations*

Code and analysis for a pre-registered audit of how 4-bit quantization changes the refusals of small chat models, with controls that ask whether a change comes from quantization or would follow from any perturbation of the same size.

Preprint forthcoming (November 2026).

## What this is about

Chat models that run on phones and laptops are usually 4-bit copies of the model that was evaluated for safety. Audits of such copies disagree: some find that quantization weakens refusal, some find it does not, some find that models refuse more. A 4-bit build is one particular perturbation of every weight, and there are many other perturbations of the same size. So a shift in its refusals could come from the structure of rounding error, or from the model's own lean under any nudge of that size.

We test three 3-4B chat models (Qwen2.5-3B-Instruct, Llama-3.2-3B-Instruct, Qwen3-4B-Instruct-2507) in the round-to-nearest formats that MLX ships for Apple Silicon. Every comparison is paired and read against an 8-bit build, which leaves likelihood unchanged. In brief:

- **Forced start.** When the first eight tokens of a compliant reply are prefilled, the default 4-bit build makes Qwen2.5-3B more likely to continue it. Llama-3.2-3B and Qwen3-4B do not move.
- **Free start.** On 400 held-out jailbreak prompts with no prefill, 4-bit Llama-3.2-3B becomes less compliant. It also refuses more benign requests written in jailbreak style, while its handling of plain safe requests is unchanged.
- **Controls.** We replace the rounding error with its mirror image, a within-group shuffle and size-matched Gaussian noise, scale it, and compare it with other quantizers in the same format (AWQ, GPTQ) and with a second runtime (llama.cpp). We also measure each build's effect on the model's refusal direction. Together these attribute each shift to the model or to the rounding.

The numbers behind every sentence in the paper are generated by one script (see *Reproducing the paper*).

## Reproducing the paper

Hardware: one Apple Silicon Mac with 16 GB of memory (we used an M2 Pro). The full set of runs takes several days of machine time; models are loaded one at a time.

```bash
pip install -e ".[test]"                    # mlx 0.32.4, mlx-lm 0.32.2
scripts/fetch_data.sh                        # refusal_direction prompt splits (Apache-2.0)
scripts/convert.sh Qwen/Qwen2.5-3B-Instruct qwen2.5-3b
scripts/convert.sh meta-llama/Llama-3.2-3B-Instruct llama3.2-3b
scripts/convert.sh Qwen/Qwen3-4B-Instruct-2507 qwen3-4b
python -m pytest tests
```

Three prompt sets are obtained from their authors and placed under `data/`:

- XSTest (Röttger et al., 2024): `data/xstest/xstest_prompts.csv`
- SORRY-Bench (Xie et al., 2024; gated on Hugging Face): `data/sorry/question*.jsonl`
- WildJailbreak evaluation set (Jiang et al., 2024; gated on Hugging Face): `data/wildjailbreak/eval/eval.tsv`

The run queues in `scripts/` list every command in the order we ran them. Each experiment skips outputs that already exist, so a queue can be stopped and restarted. Then:

```bash
python analysis/make_numbers.py    # paper/numbers.{md,json}, paper/tex/numbers.tex
python analysis/figures.py         # paper/tex/figures/*.pdf
cd paper/tex && tectonic main.tex
```

## Pre-registration

`PREREG.md` fixes the primary test, the secondary families, the human-label design, the held-out free-start test and the controls' decision rule. Each addendum is dated and was fixed before the data it concerns existed. The paper's appendix lists what was registered when and the changes to the plan.

## What is and is not released

Released: code, prompt identifiers, judge labels and human labels for every cell. Not released: model replies to harmful prompts, which stay local (`results/` is excluded from version control).
